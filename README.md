# Приём заявок нотариуса

SaaS для нотариусов: клиент выбирает услугу, видит точный перечень документов,
присылает их по защищённой ссылке или записывается на приём — заявка попадает
в общую очередь, где её разбирают сотрудники нотариуса.

Один экземпляр обслуживает много нотариусов. Каналы клиента: виджет на сайт,
Telegram и MAX — ядро от канала не зависит.

## Как это устроено

```
   виджет на сайте ─┐
   Telegram ────────┼──→  ядро: услуги, заявки, статусы, документы
   MAX ─────────────┘         │
                              ├──→ панель сотрудника (очередь заявок)
                              └──→ админка нотариуса (услуги, расписание, люди)
```

Каналы — тонкие адаптеры. Вся логика живёт в `app/domain` и ничего не знает
о том, откуда пришёл клиент. Сам разговор с клиентом — тексты, порядок вопросов,
подбор услуги — лежит в `app/channels/flow.py`, один на все мессенджеры:
Telegram и MAX отличаются только транспортом.

### Ключевые решения

**Перечень документов версионируется слепком.** При создании заявки список
документов копируется в саму заявку. Нотариус может править услугу как угодно —
у клиента останется тот перечень, который ему показали. Иначе спор
«мне сказали по-другому» неразрешим.

**Заявку захватывает ровно один сотрудник.** Захват — это один `UPDATE`
с условием «ещё никем не взята». Двое нажали одновременно — база отдаст заявку
одному, второй увидит, что его опередили.

**Документы не ходят через мессенджеры.** Клиент получает одноразовую ссылку
на наш домен и грузит файлы прямо в хранилище. Файл не оседает на чужих
серверах, ссылка живёт 30 минут и сгорает после первой загрузки.

**Файлы шифруются на диске.** В базе только метаданные, на диске — Fernet-шифр
со случайным именем. Каждое открытие документа сотрудником попадает в журнал
доступа: по 152-ФЗ оператор обязан ответить на вопрос «кто видел этот паспорт».

**Мультитенантность на уровне модели.** Столбец `tenant_id` вынесен в миксин
`TenantScoped`, все запросы фильтруются по нему. Забыть его в новой таблице —
значит открыть данные клиентов одного нотариуса другому.

## Установка

Нужны Python 3.12+ и PostgreSQL 14+.

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env` и заполните. Затем:

```bash
.venv\Scripts\python.exe -m alembic upgrade head
.venv\Scripts\python.exe -m app.seed
.venv\Scripts\python.exe -m uvicorn app.web.main:app --reload
```

Демо-нотариус после `app.seed`:

| | |
|---|---|
| Виджет | `/widget/demo` |
| Панель нотариуса | `/staff/demo/login` |
| Владелец кабинета | `owner@demo.ru` / `demo12345` |
| Сотрудник | `helper@demo.ru` / `demo12345` |
| Кабинет владельца сервиса | `/platform/login` |
| Вход туда | `admin@notarybot.ru` / `admin12345` |

## Виджет на сайт нотариуса

Одна строка перед `</body>`:

```html
<script src="https://ваш-домен/embed.js" data-notary="demo" defer></script>
```

Скрипт рисует кнопку и открывает виджет в iframe. Персональные данные вводятся
на нашем домене, а не на странице нотариуса. Атрибуты `data-label` и
`data-accent` меняют подпись и цвет кнопки.

Если у сайта уже есть своя кнопка записи, свою рисовать не нужно:

```html
<script src="https://ваш-домен/embed.js" data-notary="demo" data-launcher="none" defer></script>
```

и по клику вызывать `window.notarybot.open()`. Адрес сервиса скрипт определяет
по собственному `src`, так что при переезде на другой домен ничего менять не надо.

Домены, которым разрешено встраивать виджет, задаются в `tenant.allowed_origins` —
из них собирается `frame-ancestors`. Пустой список означает разработку.

## Мессенджеры

Оба бота используют одну и ту же логику разговора и не запускаются без токена.

**Telegram** — готов. Получите токен у `@BotFather`, впишите в `.env` и запустите:

```bash
.venv\Scripts\python.exe -m app.channels.telegram
```

Клиент приходит по ссылке `t.me/<бот>?start=<код нотариуса>` — так один бот
обслуживает нескольких нотариусов. Без ссылки попадает к `DEFAULT_TENANT_SLUG`.

**MAX** — код сверен с dev.max.ru (август 2026): база `platform-api.max.ru`,
токен заголовком `Authorization` (через query MAX больше не принимает),
`GET /updates` и `POST /messages`, события `message_created` и `message_callback`.
Транспорт покрыт тестами на моках, без обращения к их серверам.

```bash
.venv\Scripts\python.exe -m app.channels.max
```

**Но запустить его пока нельзя по нетехнической причине.** С осени 2025 MAX
публикует ботов только от верифицированных юрлиц РФ: ИП, самозанятые и
физлица зарегистрироваться не могут, а неверифицированные боты отключаются.
Нужна компания, ИНН и проверка через уполномоченного представителя.

Ещё из документации: long polling у MAX не рекомендован для продакшна —
события живут ограниченное время. При боевой нагрузке канал стоит перевести
на вебхук (`POST /subscriptions`).

## Структура

```
app/
  models/      таблицы
  domain/      логика: статусы, захват заявок, слоты, шифрование, поиск услуг
  channels/    мессенджеры: flow.py — общий разговор, telegram/ и max/ — транспорт
  web/         FastAPI: виджет, приём файлов, панель сотрудника, админка
  seed.py      демо-данные
  retention.py удаление документов по сроку хранения
alembic/       миграции
tests/         74 теста, включая сквозной путь клиента и сотрудника
```

```bash

```

Тесты идут на отдельной базе `notarybot_test` — создайте её заранее.

## Подключение нотариуса

Нотариусов подключает владелец сервиса из своего кабинета `/platform`, а не
они сами: сайт нотариуса делаете вы, и искать какую-то регистрацию он не пойдёт.

1. Заводите карточку: название, код, город, адрес, телефон, часовой пояс
   и сайты, где можно встраивать виджет.
2. Система сразу создаёт типовые услуги с перечнями и рабочие часы — нотариус
   получит рабочий кабинет, а не пустой экран.
3. Получаете одноразовую ссылку и отправляете её нотариусу любым способом.
4. Нотариус задаёт почту и пароль и попадает в свой кабинет.

Ссылка живёт 14 дней, срабатывает один раз, в базе хранится только её отпечаток.
Потерялась — выдайте новую, прежняя перестанет работать.

Поле «сайты для встраивания» задаёт `frame-ancestors` для виджета. Пусто —
встраивать можно откуда угодно, так удобно на старте; для боевого нотариуса
лучше перечислить его домены.

## Напоминания о визите

`app.reminders` шлёт клиенту два напоминания — накануне и в день приёма,
с перечнем документов и адресом. Каждое помечается в самой записи, поэтому
повторный запуск ничего не дублирует. На сервере ставится в планировщик
раз в 15–30 минут:

```bash
.venv\Scripts\python.exe -m app.reminders
```

Дойдёт только до тех, кто пришёл из мессенджера: у клиента из виджета нет
чата, ему звонит сотрудник.

## Срок хранения документов

`app.retention` стирает файлы заявок, закрытых больше `DOCUMENT_RETENTION_DAYS`
назад. Метаданные и журнал доступа остаются — они доказывают, что данные удалены.
На сервере ставится в планировщик раз в сутки:

```bash
.venv\Scripts\python.exe -m app.retention
```

## Демо без хостинга

```powershell
.\start-demo.ps1        # база, сервис и публичный туннель
.\keep-demo-alive.ps1   # держит демо живым без присмотра
```

Туннель `localhost.run` работает без аккаунта, но живёт около получаса и при
переподключении получает новый адрес. `keep-demo-alive.ps1` следит за этим сам:
перезапускает туннель, замечает смену адреса и передеплоивает сайт с новым.
Вручную то же самое делает `update-site-url.ps1 <адрес>`.

Если демо всё-таки отвалилось, сайт не ломается: кнопка записи откатывается
на собственный модал сайта.

Годится, чтобы показать продукт нотариусу. Для реальных персональных данных
нужен нормальный хостинг в РФ.

## Юридическое

Продукт рассчитан на Россию: хранение персональных данных на серверах в РФ,
152-ФЗ, нотариальная тайна. Как SaaS вы становитесь обработчиком ПД по
поручению нотариуса — нужен договор поручения с каждым нотариусом, уведомление
в РКН и политика обработки ПД. Техническая часть здесь закрыта; документы — к юристу.

Бот и виджет дают предварительную информацию и не заменяют нотариальную
консультацию. Соответствующая оговорка выведена клиенту в интерфейсе.
